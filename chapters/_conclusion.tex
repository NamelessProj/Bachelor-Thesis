\section{Conclusion}
\label{chap:conclusion}

\subsection{Summary}
This thesis presented the design, implementation, and evaluation of \nsit, a web \acrlong{vn} engine based on a declarative \gls{json} script format. The starting idea was simple: to check whether an architecture of this kind could genuinely allow non-developer authors to create and publish interactive stories without going through a local installation or a compilation step.

Over the course of the work, I defined a script \gls{schema}, built a web \glsit{runtime} in \gls{ts}/\gls{reactjs}, optimised the most expensive components, notably \texttt{Typewriter}, then added runtime validation via \gls{zod}. Three successive iterations, focused on the basics, optimisation, and robustness, made it possible to achieve the objectives classified as \textit{Must} and \textit{Should}: progressive text display, scene navigation, choice handling, format validation, and basic input handling. Some \textit{Can} features, such as \glsplit{sprite}, transitions, or saving delegated to a \gls{webworker}, were also started.


\subsection{Answer to the Research Question and Critical Assessment}
The research question concerned the ability of a web \gls{vn} engine architecture, based on a declarative format, to allow non-developer authors to create interactive content. On the technical level, the answer is positive: I showed that it was possible to describe an interactive narrative in a declarative file and run it directly in a browser, with validation mechanisms and actionable error messages.

On the other hand, the evaluation also highlights a sharper limitation from the author's point of view. The \gls{json} format, even though suited to the engine, remains sensitive to syntax errors and is not very comfortable for someone who does not come from a development background. Without a guided editor, real-time validation, or ready-to-use templates, the declarative approach alone is not enough to make content creation fully autonomous. In addition, some technical choices, such as precomputing \glslink{snaphtml}{snapshots} or delegating processing to a \gls{webworker}, improve the engine's behaviour, but also introduce trade-offs that need to be accepted depending on the context of use.

In short, the architecture is technically viable and clean, but it still needs to be surrounded by tools designed for writing in order to fully meet the initial objective.


\subsection{Directions for Development}

\subsubsection{Media Project Development Directions}
To make the solution genuinely usable by non-developer authors, several developments seem to me to be priorities:

\begin{itemize}
    \item Develop a guided editor with real-time validation (preview, explicit error messages, templates), to hide the syntactic complexity of \gls{json}.
    \item Add conversion and import tools (e.g. importing from a more readable format or from a narrative language such as Ink) to reduce the learning curve.
    \item Extend the engine with conditional branching, richer scenario variables, and an extension API to enable advanced features without modifying the core of the \glsit{runtime}.
    \item Automate the publishing pipeline (continuous integration → static deployment) and provide \textit{one-click} \textit{workflows}\footnote{\textbf{"One-click" workflow}: an automated chain of technical steps (here, building and deploying) triggered by a single user action.} for publishing stories.
    \item Improve accessibility and user documentation (step-by-step guides, examples, a template gallery).
\end{itemize}

\subsubsection{Research Directions}
Several research directions emerge from this work:

\begin{itemize}
    \item Adding a graphical or assisted editor, visual or node-based, layered on top of the declarative format, which would hide the \gls{json} syntax while retaining the advantages of plain text, such as version tracking or portability.
    \item Designing an intermediate narrative language, closer to natural language, which would then be compiled into the engine's \gls{json} \gls{schema}, in the manner of dedicated languages such as Ink or Twine.
    \item Integrating language-model-based writing assistants, capable of generating or restructuring narrative fragments directly within the declarative format.
    \item Extending the declarative model toward richer narrative logic, with persistent state variables or conditional branching, and its effect on the format's readability for a non-developer author.
    \item Standardising or ensuring the interoperability of a declarative \gls{vn} format, so that the same script could be run by several engines or platforms.
    \item Taking accessibility into account, notably for screen readers and internationalisation, directly at the level of the declarative schema rather than as a layer added afterward.
\end{itemize}

These directions open up perspectives that complement this work, by questioning how the declarative format could evolve to reconcile ease of access with narrative richness.
